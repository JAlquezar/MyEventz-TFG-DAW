PI
:
 
Interfaz de Programación de Aplicaciones, es un conjunto de definiciones y protocolos que permite a diferentes programas y aplicaciones comunicarse entre sí.
Aplicación móvil:
 
un software diseñado para ejecutarse en dispositivos móviles como smartphones y tablets, proporcionando funciones y servicios específicos a través de una interfaz de usuario interactiva.
Backend:
 parte de una aplicación o sistema que se encarga de la lógica de negocio, el procesamiento de datos y la gestión de bases de datos, funcionando en el servidor y no siendo visible para el usuario final.
Barra de navegación:
 elemento de la interfaz de usuario en aplicaciones y sitios web que permite a los usuarios acceder fácilmente a diferentes secciones o funciones a través de enlaces o menús organizados.
Base de datos:
 sistema organizado para almacenar, gestionar y recuperar datos de manera eficiente, permitiendo su acceso, manipulación y actualización de forma estructurada.
Clave foránea:
 campo en una tabla que se utiliza para establecer un vínculo entre dos tablas, apuntando a la clave primaria de otra tabla. Asegura la integridad referencial en la base de datos, manteniendo consistentes las relaciones entre las tablas.
Clave primaria:
 en una base de datos es un campo único y no nulo que identifica de manera exclusiva cada registro en una tabla, facilitando la organización y recuperación eficiente de los datos.
CMS:
 Sistema de Gestión de Contenidos, una plataforma de software que permite crear, gestionar y modificar contenido digital en un sitio web de manera sencilla, sin necesidad de conocimientos avanzados de programación.
Escalabilidad:
 capacidad de un sistema para manejar un aumento en la carga de trabajo o expandirse en tamaño de manera eficiente. Esto implica que el rendimiento del sistema mejora o se mantiene constante a medida que se agregan más recursos o se incrementa la demanda.
Esquema entidad-relación:
 representación visual de los datos y sus interrelaciones dentro de un sistema de base de datos, utilizando diagramas que muestran entidades (objetos o conceptos) y las relaciones entre ellas.
FastAPI
:
 framework de desarrollo web para construir APIs (Interfaz de Programación de Aplicaciones) en Python de manera rápida, fácil y con alto rendimiento. Se destaca por su sintaxis intuitiva, tipado estático opcional y su capacidad para generar documentación automática basada en estándares OpenAPI y Swagger.
Framework:
 una estructura de software predefinida que proporciona un conjunto de herramientas, bibliotecas y directrices para facilitar el desarrollo y la integración de aplicaciones de manera más eficiente y estandarizada.
Frontend:
 parte de una aplicación o sitio web que interactúa directamente con los usuarios. Incluye todo lo que los usuarios ven, interactúan y experimentan en su navegador web, como la interfaz de usuario, el diseño, la disposición de los elementos, las animaciones y cualquier otro contenido visible o interactivo.
ID:
 campo comúnmente utilizado en las bases de datos para referirse a la clave primaria. Es un valor único asignado a cada registro en una tabla, que permite identificar y diferenciar de manera exclusiva cada entrada dentro de esa tabla.
JavaScript:
 lenguaje de programación ampliamente utilizado tanto en el frontend como en el backend de las aplicaciones web. En el contexto del frontend, JavaScript se utiliza para agregar interactividad y dinamismo a las páginas web, permitiendo a los desarrolladores crear efectos visuales, manipular el contenido de la página en respuesta a las acciones del usuario y comunicarse con servidores web para obtener o enviar datos sin tener que recargar la página.
Lenguaje de programación:
 conjunto de reglas y sintaxis que permite a los desarrolladores escribir instrucciones que una computadora puede entender y ejecutar para realizar tareas específicas.
Librería:
 conjunto de funciones, métodos y rutinas predefinidas que proporcionan funcionalidades específicas para ser utilizadas por programas o aplicaciones. Las librerías permiten a los desarrolladores ahorrar tiempo y esfuerzo al reutilizar código ya escrito y probado, en lugar de tener que escribirlo desde cero.
MySQL:
 sistema de gestión de bases de datos relacional de código abierto ampliamente utilizado. Es conocido por su confiabilidad, rendimiento y facilidad de uso, y es compatible con una amplia gama de plataformas y lenguajes de programación. MySQL es una opción popular para aplicaciones web y se utiliza en una variedad de entornos, desde pequeños sitios web hasta grandes sistemas empresariales.
Plugin:
 componente de software que se puede agregar a una aplicación o sistema para extender su funcionalidad o modificar su comportamiento. Los plugins generalmente se diseñan para integrarse fácilmente con el software principal y pueden proporcionar características adicionales, como nuevas herramientas, efectos, funcionalidades específicas o soporte para formatos de archivo adicionales. Los usuarios pueden instalar, desinstalar o activar plugins según sus necesidades, lo que permite una mayor personalización y flexibilidad en el uso del software.
React:
 biblioteca de JavaScript de código abierto utilizada para construir interfaces de usuario interactivas y dinámicas para aplicaciones web y móviles. Desarrollada por Facebook, React se centra en la creación de componentes reutilizables que representan partes específicas de la interfaz de usuario y que pueden actualizarse de manera eficiente cuando cambia el estado de la aplicación. Utiliza un enfoque basado en componentes y el concepto de un DOM virtual para optimizar el rendimiento y facilitar el desarrollo de aplicaciones de una sola página (SPA) y aplicaciones de interfaz de usuario complejas.
React Native:
 
marco
 de desarrollo móvil que permite a los desarrolladores crear aplicaciones nativas para iOS y Android utilizando JavaScript y React. Con React Native, pueden compartir una gran parte del código entre plataformas, lo que acelera el desarrollo y reduce los costos. La plataforma aprovecha la potencia de React para construir interfaces de usuario intuitivas y utiliza componentes nativos del sistema operativo para lograr un rendimiento óptimo y una apariencia nativa.
Relación 1:M:
 un registro en una tabla puede estar relacionado con múltiples registros en otra tabla, pero cada uno de estos registros múltiples está vinculado solo a un único registro en la primera tabla.
Relación N:M:
 múltiples registros en una tabla pueden estar relacionados con múltiples registros en otra tabla. Esto suele implementarse mediante una tabla intermedia que contiene claves foráneas de ambas tablas para establecer las relaciones.
Sistema gestor de bases de datos:
 software diseñado para gestionar, almacenar, organizar y recuperar datos de manera eficiente en una base de datos. Estos sistemas ofrecen funcionalidades como la creación y modificación de bases de datos, el manejo de transacciones, la administración de usuarios y permisos, así como la optimización del rendimiento de consultas y almacenamiento de datos. Ejemplos comunes de SGBD incluyen MySQL, PostgreSQL, Oracle, SQL Server y MongoDB.
Web:
 sistema de información global accesible a través de Internet, que utiliza protocolos como HTTP y HTTPS para permitir la visualización y navegación de contenido multimedia mediante navegadores web.
Wordpress:
 un CMS de código abierto ampliamente utilizado para la creación y gestión de sitios web y blogs. Se destaca por su facilidad de uso, flexibilidad y extensibilidad a través de una amplia variedad de temas y complementos (plugins). Con WordPress, los usuarios pueden crear y personalizar fácilmente sitios web sin necesidad de conocimientos de programación, gracias a su interfaz intuitiva y a su editor de contenido visual. Es una opción popular tanto para pequeños blogs como para grandes sitios web corporativos, y su comunidad activa ofrece soporte y recursos adicionales para los usuarios.

2. DESCRIPCIÓN DEL PROYECTO
2.1. ANÁLISIS GENERAL DEL PROYECTO
Estamos desarrollando una aplicación web que revolucionará la forma en que las personas organizan actividades en Zaragoza. Con esta herramienta, podrás crear tus propios eventos o unirte a los de otros en la zona. Nuestra aplicación surge de la creciente necesidad de socializar y conectar con personas afines, una necesidad que ha sido aún más evidente desde la pandemia del COVID-19 en 2020.
Si bien existen otras aplicaciones similares, creemos que nuestra propuesta ofrece elementos clave que marcarán la diferencia. Nuestro objetivo es facilitar la socialización en la ciudad y ayudar a combatir la soledad, conectando a personas con intereses comunes y proporcionando experiencias significativas.
2.1.1. ABORDAR UNA NECESIDAD UNIVERSAL
Todos hemos experimentado momentos de soledad o hemos sentido el deseo de ampliar nuestro círculo social. Con nuestro proyecto, abrimos oportunidades para facilitar la socialización y explorar nuevas experiencias. Ofrecemos una plataforma directa para conectar con personas que comparten tus mismos intereses y aficiones, lo cual consideramos fundamental para agilizar el proceso de establecer nuevas amistades.
Además, cubriremos la falta de información sobre diferentes actividades y eventos, la soledad y la dificultad para encontrar compañía con intereses similares son algunos de los principales problemas a los que nos enfrentamos la mayoría de la población, problemas que MyEventZ está dispuesto a solucionar.
2.1.2. A QUIENES NOS DIRIGIMOS
En nuestra aplicación, si bien está abierta a todo tipo de usuarios, nos enfocamos especialmente en 
dos grupos clave
: aquellos que se trasladan a Zaragoza por motivos de estudio o trabajo y se encuentran en una situación donde no conocen a nadie en la ciudad, y aquellos que enfrentan dificultades para socializar o encontrar personas con intereses similares.
Para los 
recién llegados a la ciudad
, nuestra plataforma les ofrece una oportunidad invaluable para conectarse con otros residentes, descubrir eventos locales y sumergirse en la vida social de Zaragoza desde el primer día. Creemos que esto no solo facilita su adaptación a un nuevo entorno, sino que también brinda un sentido de comunidad.
Por otro lado, para aquellos que encuentran 
difícil socializar
 o encontrar 
personas con intereses afines
, nuestra aplicación actúa como un puente que les permite descubrir a otros con quienes compartir sus pasiones y hobbies. Ya sea que se trate de aficionados al arte, amantes de la música, deportistas o cualquier otra cosa, nuestra plataforma les ofrece una vía directa para conectarse con personas que comparten sus mismas afinidades, fomentando así nuevas amistades y relaciones significativas.
2.1.3. ¿QUÉ SERÍA DE ZARAGOZA SIN NOSOTROS?
Sin duda, Zaragoza es una ciudad llena de vida, pero nuestra aplicación puede enriquecer aún más la experiencia social de quienes la habitan. Algunas de las razones por las que Zaragoza sin nuestra aplicación podría perder ciertos aspectos de su vida social son:
Dificultad para conocer gente nueva:
 Sin una plataforma que facilite la conexión entre personas con intereses similares, aquellos que llegan a Zaragoza por primera vez, podrían tener dificultades para integrarse y establecer nuevas amistades.
Limitaciones en la diversidad de actividades:
 Nuestra aplicación amplía el acceso a una variedad de eventos y actividades en Zaragoza, lo que permite a los residentes explorar nuevas experiencias y descubrir oportunidades que de otra manera podrían pasar desapercibidas.
Mayor riesgo de aislamiento social:
 Para aquellos que enfrentan dificultades para socializar o encontrar personas con gustos similares, la falta de una plataforma como la nuestra podría aumentar el riesgo de aislamiento social y la sensación de soledad en la ciudad.
Menor sentido de comunidad:
 La posibilidad de conectar con otros residentes a través de nuestra aplicación fortalece el sentido de comunidad en Zaragoza, fomentando la colaboración, el apoyo mutuo y el intercambio cultural entre sus habitantes.
2.1.4. ¿QUÉ VENTAJAS OFRECEMOS?
Nuestra aplicación busca diferenciarse del resto de aplicaciones similares que se encuentran en el mercado mediante de los siguientes factores:
Aportamos un 
enfoque local
, centrándonos específicamente en la ciudad de Zaragoza y alrededores, por lo que aspiramos a un público mucho más específico y fácil de atraer.
Ofrecemos un

 con las que etiquetar los eventos, de forma que no se quede atrás ningún tipo de actividad que quieran organizar los usuarios de la aplicación.

facilitar la conexión entre usuarios
.

Es importante destacar que desde MyEventZ ofreceremos una serie de servicios complementarios para que nuestros usuarios puedan disfrutar de una mejor experiencia a la hora de hacer uso de nuestra aplicación. Es por esto que tendrán acceso a las siguientes características:
Asesoramiento personalizado:
 todos los usuarios tendrán acceso a diferentes opciones de contacto con el equipo de MyEventZ para solicitar cualquier tipo de ayuda acerca del uso de la aplicación para que puedan aprovechar al máximo todas sus características.

3.1. ESTUDIO DEL SECTOR
3.1.1. EVOLUCIÓN Y TENDENCIAS
A causa de la pandemia del COVID-19 hubo una gran disminución de los eventos presenciales durante 2020 y 2021, lo que causó un crecimiento de los eventos online, conforme se ha ido regresando a la normalidad, realizando por tanto más eventos presenciales, se ha visto un incremento de la búsqueda de eventos híbridos y de experiencias más personalizadas.
3.1.2. ANTE LOS PRODUCTOS SUSTITUTIVOS
Dado que hay cierta competencia dentro de nuestro sector debemos tener en cuenta algunas estrategias para actuar en caso de que otra aplicación destaque sobre la nuestra. Para enfrentarnos a esto hemos pensado en los siguientes puntos:
Enfoque local:
 Como mencionamos previamente al ser una aplicación centrada principalmente en Zaragoza podemos ser capaces de centrarnos más específica y fácilmente en 
nuestro público.
Variedad de los eventos:
 Mientras que otras aplicaciones pueden enfocarse en un tipo de evento especializado como podría ser 
Nixel 
con las fiestas en discotecas, nosotros abordaremos un 
terreno mucho más amplio
.
Foco en nuestra audiencia:
 Algo que hemos visto que falla en otras aplicaciones similares es que crean la aplicación, la lanzan al público y no la mantienen periódicamente ni atienden debidamente a sus clientes. Esto es algo en lo que nos vamos a centrar en evitar, dado que creemos que solo así podremos crear una comunidad sólida y estable, que se mantenga fiel a nuestro producto.
En conclusión pretendemos que nuestro principal escudo frente a los productos sustitutivos sea la
 cercanía con el usuario/cliente
, combinado con el
 buen trato y atención
.

Para explorar la viabilidad y futuro de nuestro proyecto, hemos realizado un análisis de las principales debilidades, amenazas, fortalezas y oportunidades que envuelven nuestro proyecto y cómo pueden afectar a su desarrollo.
3.5.1. DEBILIDADES
Dependencia tecnológica:
 
la aplicación depende de la estabilidad y compatibilidad con los dispositivos móviles. Problemas técnicos, actualizaciones de sistemas operativos o cambios en las plataformas pueden afectar negativamente la funcionalidad de la aplicación, por lo que habrá que atender todos los posibles reportes sobre problemas que puedan experimentar los usuarios. Además, habrá que tener un constante mantenimiento de los servicios de los que dependa la aplicación, como por ejemplo los servidores de bases de datos.
Financiación:
 
el desarrollo y lanzamiento de una aplicación móvil exitosa requieren una inversión significativa en desarrollo de software, diseño, marketing y posiblemente servidores para manejar la carga de usuarios. Esto es algo importante a tener en cuenta ya que no gozará de la popularidad que tiene como objetivo a alcanzar hasta pasadas las fase inicial de desarrollo y lanzamiento.
Falta de popularidad inicial:
 
nos enfrentaremos a la dificultad de atraer usuarios debido a su falta de reconocimiento provocado por la competencia existente o a la falta de conciencia sobre la aplicación. Se requerirá una estrategia de marketing sólida mediante el uso de redes sociales, colaboraciones con influencers locales y campañas publicitarias específicas de Zaragoza pueden ser clave para aumentar la visibilidad y atraer a los primeros usuarios.

Competencia local:
 
la existencia de aplicaciones similares centradas en eventos puede generar una competencia directa. Cambio en los hábitos de los usuarios:
 
los cambios de preferencias por diferentes tipos de eventos o formas de socializar, pueden afectar la demanda de la aplicación. Es fundamental tener un enfoque flexible y mantener actualizaciones con respecto a las tendencias sociales.
Obsolescencia:
 
la constante evolución de la tecnología móvil puede llevar a la obsolescencia de la aplicación si no se actualiza regularmente. Deberemos planificar actualizaciones de forma frecuente para generar un sentimiento de desarrollo e innovación entre nuestros usuarios.

4. REQUISITOS DEL SISTEMA
4.1. REQUISITOS FUNCIONALES
A continuación, proporcionaremos los requisitos funcionales de nuestra aplicación, donde detallaremos las funciones específicas que realizará su software:
1. Registrar una nueva cuenta: 
En caso de que un usuario no tenga una cuenta, podrá crear una nueva indicando sus datos (nombre, apellidos, nombre de usuario, correo, contraseña, …). La tarea debe tener un campo para el nombre, descripción y fecha de vencimiento.
2. Inicio de sesión: 
El usuario podrá acceder a la aplicación con su cuenta personal haciendo uso de sus credenciales de inicio de sesión (nombre y contraseña).
3. Mostrar eventos publicados: 
Cuando un usuario inicie sesión, 
accederá
 al “centro de eventos” donde serán mostrados diferentes listados de eventos que le puedan ser de interés.
4. Filtrar eventos: 
Dentro del “centro de eventos” se encontrará una sección de filtrado, donde el usuario podrá listar eventos en base a diferentes parámetros que indique, como tipo de evento, número de participantes, edad o precio entre otros.
5. Visualizar información de un evento: 
Si un usuario desea conocer más información sobre alguno de los eventos que le han sido mostrados a lo largo de los diferentes listados, tendrá la posibilidad de acceder a una nueva pantalla, en la que le será mostrada toda la información disponible sobre el mismo en mayor detalle.
6. Participación en un evento: 
Al acceder a la vista detallada de un evento, el usuario podrá apuntarse al mismo, y quedará listado entre todos los usuarios que han decidido participar. También contará con la posibilidad de 
desapuntarse
 en caso de que lo desee.
7. Acceso al perfil de usuario: 
Los usuarios podrán acceder a su perfil, donde se mostrará la información de su cuenta. A su vez, podrán editar algunos de sus datos y actualizarlos en la base de datos.
8. Publicar nuevos eventos: 
Un usuario podrá publicar nuevos eventos con su respectiva información, como por ejemplo: lugar, fecha, rango de edad, categoría, descripción, requisitos, …
9. Ver eventos publicados: 
Podrá acceder a un listado de eventos que tenga publicados actualmente. Además, podrá visualizar un historial de todos los eventos publicados con anterioridad y que ya se hayan realizado.
10. Listar eventos en los que se ha participado: 
Los usuarios contarán con un listado de, tanto los eventos con los que están apuntados actualmente, como un historial de eventos en los que ya haya participado.
11. Guardar eventos en lista de deseados: 
Si un usuario está interesado en participar en un evento, pero aún no está decidido a inscribirse, podrá guardarlo en un listado personal de “deseados”.

4.2. REQUISITOS NO FUNCIONALES
A continuación mostraremos los requisitos centrados en propiedades del sistema, estableciendo las limitaciones o restricciones del mismo:
1. Usabilidad: 
Interfaz intuitiva y agradable para el usuario, capaz de adaptarse a diferentes tamaños de pantalla.
2. Compatibilidad: 
Funcionamiento en la mayor cantidad posible de dispositivos móviles con sistema operativo Android. Integración con características nativas del dispositivo como el GPS.
3. Seguridad: 
Correcto almacenamiento y tratamiento de datos del usuario, cumpliendo con la Ley Orgánica de Protección de Datos. Uso de métodos de autenticación y acceso seguros, usando técnicas de cifrado cuando sea necesario.
4. Rendimiento: 
Ofrecer tiempos de carga lo más reducidos posible, para ofrecer una experiencia de usuario lo más ininterrumpida posible. La aplicación podrá funcionar en dispositivos tanto de alta, como de media y baja gama.
5. Escalabilidad: 
La aplicación estará lo más optimizada posible para que no sufra bajones de rendimiento en caso de que haya un aumento de los usuarios concurrentes. El servidor de bases de datos será capaz de gestionar la información de una gran cantidad de eventos y usuarios.
6. Accesibilidad: 
La interfaz y funciones serán lo más intuitivas posible, para que cualquier nuevo usuario pueda hacer uso de ellas sin apenas ningún conocimiento previo. La aplicación podrá ser usada en dispositivos de todas las gamas, de forma que estos no sean un impedimento a la hora de hacer uso de ella.
7. Mantenimiento: 
La aplicación se mantendrá actualizada de forma constante, solucionando posibles problemas de funcionamiento que reporten nuestros usuarios y añadiendo posibles nuevas funcionalidades que optimicen o mejoren la experiencia de usuario.

5. PROTOTIPADO DE PANTALLAS
A continuación vamos a revisar la 
interfaz de la aplicación
 y las
 funcionalidades principales
. Primero, al abrir la aplicación, nos encontraremos con el
 inicio de sesión
, donde deberemos indicar nuestras credenciales para poder acceder. Si las credenciales son incorrectas, se le notificará al usuario a través de un mensaje en pantalla.
Al iniciar sesión, el usuario 
accederá
 con un 
token identificativo
 el cual le servirá para ese inicio de sesión único, aumentando así la seguridad de la aplicación
En caso de que un futuro usuario no cuente todavía con una cuenta registrada en la aplicación, podrá 
crear una nueva
 especificando los datos indicados a lo largo de las pantallas de registro de usuario.
Una vez hayamos accedido con nuestra cuenta, se nos mostrará la 
pantalla principal
 en la que se mostrará un listado con los eventos publicados 
más populares
 del momento, es decir, aquellos pendientes de realizar que cuenten con una mayor cantidad de participantes inscritos.
Justo debajo, se 
listarán
 aquellos 
eventos más próximos
, sin importar el número de participantes o categorías asignadas.
En la parte inferior, observaremos una 
barra de navegación
 a través de la cual podremos viajar al resto de secciones de la aplicación.
Al presionar el segundo botón de la barra de navegación comenzando por la izquierda, como queda marcado en la imagen, 
abriremos
 la 
sección de categorías 
de la aplicación. Aquí podremos buscar entre la gran variedad de categorías de actividades, deportes, hobbies, etc. de las que dispone la aplicación. Cuando seleccionemos una o varias de estas categorías, se realizará un filtrado entre todos los eventos publicados por nuestros usuarios, mostrando únicamente aquellos cuyas categorías coincidan con las que hemos seleccionado. 
Cuando hayamos filtrado por categorías, se nos mostrará una pantalla muy similar a la inicial visualizando los eventos filtrados. Además, aparecerán dos botones, uno de ellos para volver a la selección de categorías, y el otro para eliminar todos los filtros. Así, podremos acceder a los eventos que puedan coincidir con nuestros intereses.
Cuando 
accedamos
 a cualquiera de los 
eventos
, se nos mostrará toda la información correspondiente sobre el mismo. Entre esta información encontraremos:
Título del evento.
Fecha y hora de realización.
Categorías relacionadas.
Descripción del evento.
Rango de edad permitido.
Ubicación en la que se realizará.
Organizador y participantes.
En la parte inferior, se encontrará el botón con el que los usuarios podrán alistarse a la actividad, aunque en caso de que ya estén inscritos, les dará la opción de desapuntarse.
En caso de que el evento sea uno organizado por tí mismo, tendremos la opción de eliminarlo.
A través del penúltimo botón de la barra de navegación podremos buscar (por nombre, apellidos o usuario) entre todos los
 usuarios
 que están registrados en la aplicación y acceder a la información de su perfil, donde se mostrará:
Nombre completo.
Nombre de usuario.
Biografía.
Categorías de su interés.
Eventos publicados.
Actividades participadas.
Redes sociales.
Con el último botón de la aplicación se podrá mostrar el 
perfil del usuario
 con el que se ha iniciado sesión. A diferencia de la pantalla anterior, en esta se mostrarán dos botones con los que el usuario podrá acceder a la pantalla de edición de datos de su cuenta, o cerrar sesión.
Finalmente, usando el botón central de la barra de navegación, accederemos a la pantalla de configuración y 
publicación de eventos
, donde podremos especificar todos los datos de una actividad que queramos realizar.
6. BASE DE DATOS DEL SISTEMA
A continuación analizaremos la base de datos en la que se almacenará toda la información de la aplicación, revisando primero las tablas principales y después las relaciones que las unen.
6.1. ENTIDADES
Primero, analizaremos cada una de las entidades principales que componen el esquema, indicando los datos que contienen.
USUARIOS
Contiene el nombre completo de los usuarios, fecha de nacimiento, biografía que quiere que se muestre en su perfil y redes sociales (Instagram, X, YouTube y TikTok). Además se almacenará el nombre de usuario y la clave, que servirán de credenciales para el inicio de sesión. De más está decir que la 
ID
 
de usuario será la 
clave primaria
 y se utilizará para identificar de forma más eficaz al usuario a nivel de backend.
EVENTOS
Almacenará el título, fecha y hora de realización, descripción, rango de edad, ubicación y número máximo de participantes de un evento publicado. Además de su clave primaria, almacenará como 
clave foránea
 la ID del usuario que haya publicado el evento, el cual, se mostrará como organizador y participante en la pantalla correspondiente de la aplicación. De esta forma también se podrán listar rápidamente los eventos publicados por cada usuario.
CATEGORÍAS
Almacenará la ID y el nombre de cada categoría. Estas categorías servirán tanto para etiquetar los eventos como para mostrar los hobbies y gustos de los usuarios.
6.2. RELACIONES
Vamos a ver cómo interactúan las tablas principales y para qué sirven estas relaciones dentro de la aplicación.
USUARIOS > EVENTOS
Esta es una 
relación 1:N
 entre usuarios y eventos, ya que un usuario será capaz de publicar muchos eventos, pero un evento solo 
pertenecerá
 a un organizador.
USUARIOS_HOBBIES
Una 
relación N:M
 entre usuarios y categorías, ya que un usuario puede estar interesado en varias categorías y una categoría puede ser seleccionada por varios usuarios.
EVENTOS_CATEGORIAS
Relación N:M similar a la anterior. Un evento puede ser etiquetado con diferentes categorías y una categoría puede servir para catalogar muchos eventos.
PARTICIPANTES_EVENTOS
Relación N:M que almacena los “tickets” de cada participación en un evento. Además de guardar los IDs de usuario y 
evento
, almacena la fecha en la que se ha apuntado el usuario.

8. PLAN DE MARKETING
8.1. OBJETIVOS A CORTO, MEDIO Y LARGO PLAZO
8.1.1. GENERALES
Nuestro objetivo principal consiste en 
posicionar a MyEventZ como la
 
principal aplicación
 de gestión y descubrimiento de eventos en Zaragoza dentro del primer año de operación una vez sido lanzada de forma oficial, mejorando significativamente la 
conectividad 
y el 
acceso 
a eventos culturales y sociales para los residentes y visitantes.
Somos conscientes de que se trata de un objetivo bastante ambicioso, pero a pesar de ello y gracias a la poca competencia en el sector y la calidad de la misma, creemos que podemos alcanzarlo con un 
buen plan de marketing
 y utilizando las herramientas adecuadas.
8.1.2. ESPECÍFICOS
En cuanto a los objetivos específicos, hemos desarrollado un listado de metas a alcanzar especificando el qué queremos conseguir, cuando lo queremos conseguir, y cómo lo vamos a conseguir. Entre ellos los que más destacan son los siguientes:
Aumentar la base de usuarios en
 
un 20% trimestralmente
 mediante estrategias de marketing digital y colaboraciones. De esta forma no solo nos beneficiamos nosotros mismos como empresa y aplicación, sino que también los propios usuarios tienen una comunidad y ecosistema más grande donde encontrar más eventos diversos, personas con las que poder realizarlos, posibilidades y gente nueva…
Establecer al menos cinco alianzas estratégicas
 
con organizadores de eventos locales para promover la aplicación antes del lanzamiento definitivo. Esta meta es esencial para así poder dar a conocer la aplicación lo mejor posible y llegando a la mayor cantidad de gente posible, de forma que podamos crear una base inicial de usuarios activos para que pueda tener vida la propia aplicación, ya que por su propia naturaleza, requiere de usuarios para que puedan existir los eventos, se llenen, y puedan ser atractivos para el resto de usuarios existentes y/o nuevos usuarios.
Mejorar la retención de usuarios activos
 en al menos un 
30%
 a través de la implementación de características de gamificación y recompensas dentro de la app. Gracias a este objetivo, seremos capaces de tener actividad diaria dentro de la aplicación a pesar de tener cualquier cantidad de usuarios registrados, ya que la actividad es la principal fuente de contenido nuevo en la aplicación a parte de los eventos que puedan organizar entidades oficiales y certificadas (empresas que quieran colaborar con nosotros) o actividades que podamos organizar nosotros mismos para animar e incentivar a la comunidad a utilizar la aplicación y realizar eventos sociales.
8.2. COMUNICACIÓN
Además de contar con una aplicación sólida y completa, es esencial establecer una 
buena comunicación con los usuarios
 potenciales para dar a conocer nuestra app de forma amplia y eficaz. Por suerte, estamos enfocados en un público relativamente reducido (habitantes de la ciudad de Zaragoza), algo que nos puede ser una gran ventaja para 
publicitarla y
 que la gente sepa de ella.
Como primer paso, decidimos crear 
cuentas oficiales en redes sociales
 para la aplicación, como forma de publicidad inicial durante su desarrollo. En este periodo, nos dedicaremos a publicar entrevistas a gente aleatoria sobre temas que puedan estar relacionados con la aplicación (actividades que le gusta realizar a la gente, soledad, alternativas que toman para socializar, la posibilidad de usar una aplicación que les ayude a solventar problemas relacionados,…). De esta forma, comenzaremos a hacer eco en la ciudad y la gente tendrá una mínima idea sobre quiénes somos y lo que pretendemos conseguir.
Una vez lleguemos a las fases finales del desarrollo, contactaremos con dos de las cuentas con más influencia en redes sociales de toda Zaragoza: 
SoydeZaragoza y Zinderizar
. Ambas se dedican a dar voz a eventos, apoyar actividades sociales en la ciudad, incluso llegando a organizar sus propias fiestas y eventos para que la gente acuda a vivir nuevas experiencias y formar amistades. El plan consistiría en presentarles nuestro prototipo final de aplicación, mostrarles como ambos buscamos suplir las mismas necesidades y cómo a todos nos beneficiaría colaborar. Gracias a esto, obtendremos un gran foco de publicidad y atención, mientras que ellos contarán con una aplicación que les facilite la organización de actividades.
Finalmente, tras haber establecido nuestra presencia en la ciudad y redes sociales locales, en caso de que la aplicación obtenga un alcance suficiente como para ser considerada una “app oficial de Zaragoza”, planeamos contactar y colaborar con el propio 
ayuntamiento
 para lograr un mayor control, seguridad y fiabilidad de los eventos y la app. Así lograremos una presencia total de la aplicación, habremos alcanzado nuestro público prácticamente en su totalidad o incluso más y tendremos más posibilidades de 
escalabilidad
 y expansión de cara a futuro.

necesarios para ciertos tipos de eventos y/o actividades como puede ser una quedada para ir a ver una película al cine, o una actividad que tenga un costo predefinido.

2,99€ al mes

siendo un precio justo, muy competitivo, y 
asequible para el público objetivo

donaciones

cosméticos premium

9.5. PRESUPUESTO DEL PRODUCTO FINAL
A pesar de que este es un proyecto de pasión por la ciudad en la que vivimos, su gente y los que están por llegar, la aplicación debe generar un beneficio suficiente como para, como mínimo, cubrir la
 inversión inicial
 y
 gastos de mantenimiento
 (servidores, dominio, entornos de desarrollo, publicidad, ….).
Podríamos tomar como ejemplo “
Click and Plan
”, la cual es de entre todas las competidoras, la más similar a nuestro proyecto, tratando de obtener así una previsión realista del desarrollo económico que podría tener nuestra app. El último registro oficial del número de usuarios activos en esta app es de 2020, contando con un aproximado de 
20.000 usuarios activos
 según la descripción de la empresa mostrada en LinkedIn. A pesar de contar con esta cifra, es muy probable que diste mucho de la actual. Además, la aplicación genera beneficios en base al número de asistentes a las actividades de pago publicadas y no cuenta con ningún plan de pago para los usuarios, por lo que resulta complicado e impreciso evaluar los beneficios de esta empresa. Es por esto que nos hemos basado en estadísticas y previsiones propias para establecer el precio y desarrollo económico de nuestra app.
A fecha de realizado este documento y según el Instituto Nacional de Estadística, en Zaragoza residen un total de 
111.406 personas
 cuyo rango de edad se encuentra entre los 16 y los 30 años, siendo este nuestro público objetivo.
Teniendo en cuenta la positividad con la que fue recibida nuestra idea tanto en las entrevistas como en las encuestas, podemos prever que, contando con las respuestas a la par de ser realistas, un aproximado del 
25%
 de nuestro público objetivo hará uso de nuestra app. Equivaliendo así a unos 
27.800 usuarios activos
 en la aplicación una vez alcanzada su estabilidad.
Si conseguimos la fidelidad de nuestros usuarios y su satisfacción, calculamos que un 
15%
 de estos se animarán a actualizar sus cuentas con el plan de pago (2.99€), es decir, unos 
4.050 usuarios “premium”
. De esta forma, obtendremos un  beneficio aproximado de 
12.109€ mensuales
 en un punto estable.
Sobra mencionar que esto son previsiones que pueden no reflejar los resultados reales, pero observando las estadísticas, podemos concluir que, con el precio opcional establecido, no será complicado 
recuperar la inversión
 ni 
cubrir los gastos
 de mantenimiento.
10. CONCLUSIONES
Tras haber desarrollado en profundidad nuestra idea y haber analizado detenidamente todas las posibilidades, estadísticas y estrategias a seguir, hemos alcanzado una 
visión sólida y factible
 para la aplicación que queremos desarrollar.
Pretendemos cubrir una de las necesidades más primarias y demandadas por el ser humano, la 
socialización 
y el 
miedo a la soledad
. Este es un problema que aumentó especialmente tras la pandemia de 2020, aunque no necesariamente todo el 
mundo que lo
 sufra sea debido a este evento. También es el caso de gente que se tiene que mudar por motivos de trabajo o estudio a otras ciudades en las que no conocen a nadie, siendo difícil encontrar un nuevo círculo social en el que sentirse acogido.
Es por esto que surgió MyEventz, una aplicación con la que 
gestionar y organizar actividades
, fiestas y eventos de cualquier tipo con el objetivo de ayudar a la gente de Zaragoza a encontrar otras personas con sus mismos gustos e intereses, agilizando enormemente el proceso de socialización.
Uno de nuestros puntos fuertes es que, debido a nuestro 
enfoque local
 en la ciudad de Zaragoza y sus alrededores, será mucho más fácil 
publicitarla
 y darla a conocer que si 
abarcáramos
 un público mucho más amplio. Esto será especialmente efectivo si logramos establecer alianzas con diferentes 
medios de difusión y redes sociales
 como pueden ser SoydeZaragoza y Zinderizar.
A pesar de ser este un proyecto de amor y pasión por nuestra ciudad, hemos logrado establecer un precio opcional, estrategia y previsión con los que podremos recuperar la inversión inicial, mantener sin dificultad la aplicación e incluso resultar bastante
 rentable económicamente
 a medio y largo plazo.
